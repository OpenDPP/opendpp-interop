## Artifacts
- `battery-vc.jwt` — the enveloping `vc+jwt` (paste into jwt.io / a JOSE debugger).
- `battery-vc-credential.json` — the decoded credential payload (SKU/type, `idGranularity:"model"`).
- `battery-unit-vc.jwt` / `battery-unit-vc-credential.json` — a PER-UNIT credential for one serialised battery (`idGranularity:"item"`, the real GS1 AI-21 serial as `itemNumber`, #123).
- `textile-vc.jwt` / `textile-vc-credential.json` — a NON-BATTERY (textiles) credential (#119): fiber composition mapped to typed `materialProvenance` + a self-declared circularity `performanceClaim`; `facilityDetails` masked out. Verifies against the same `battery-issuer-did.json`.
- `battery-vc.sdjwt` — the credential as an SD-JWT-VC (`<JWS>~<disclosure>~…`, typ `dc+sd-jwt`, with `iss`+`vct`, #118): selective disclosure of `credentialSubject` claims, all disclosures present.
- `battery-vc-presented.sdjwt` — a HOLDER presentation revealing only `countryOfProduction` + `materialProvenance`; the other disclosable claims remain opaque `_sd` digests, yet it still verifies (#118).
- `battery-vc-di.jsonld` — the credential with an EMBEDDED W3C Data Integrity proof (`ecdsa-jcs-2019`, #117) — the alternative to the enveloping `vc+jwt`.
- `battery-unit-vc-di.jsonld` — the PER-UNIT embedded Data Integrity credential (item granularity, #117 follow-up).
- `battery-unit-vc.sdjwt` — the PER-UNIT credential as an SD-JWT-VC (item granularity, #251 RE-Q) — parity with `battery-vc.sdjwt`.
- `battery-issuer-did.json` — the issuer `did:web` document (served live at `/tenants/<id>/did.json`).

> The sample is signed with an **ephemeral demo key**; production signs with the tenant's eIDAS vault
> key. The CI-enforced checks live in `tests/functional/vc-{emitter,jose-proof,verifier}.test.ts`.
